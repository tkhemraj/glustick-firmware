Which path are you on?

Two ways to use Glustick Link hardware. Most families should start with Meshtastic.

Recommended

Path 1 — Meshtastic

No custom firmware needed

Flash off-the-shelf Meshtastic firmware. Plug one board into your server, hand the other to your kid. The Glustick Family server speaks Meshtastic's serial protocol natively — no gateway, no ChirpStack, no infrastructure.

1 Buy two Heltec WiFi LoRa 32 V3 boards
2 Flash Meshtastic firmware via their web flasher
3 Set MESHTASTIC_PORT=/dev/ttyACM0 in your server .env
4 Enter the kid's 8-character node ID in the Glustick Family app
No gateway No ChirpStack Works immediately
Flash Meshtastic →

Path 2 — Custom Firmware

LoRaWAN + WiFi fallback

OTAA join to a LoRaWAN gateway. Uplinks route through ChirpStack → MQTT → Glustick Family server. Longer range through proper gateway infrastructure, plus WiFi sync when the device is home.

1 Set up a LoRaWAN gateway + ChirpStack v4
2 Build and flash this firmware with PlatformIO
3 Provision with the Glustick Family app via BLE or QR
4 Enable the lora Docker Compose profile on your server

Building the firmware

Install PlatformIO Core or the VS Code extension, then run one command.

bash 
# Install dependencies and build
pio run -e heltec_v3

# Flash to a connected device
pio run -e heltec_v3 --target upload

# Open the serial monitor (115200 baud)
pio device monitor
bash 
# EU868 build
pio run -e heltec_v3_eu868

# Flash to a connected device
pio run -e heltec_v3_eu868 --target upload

# Open the serial monitor
pio device monitor
LMIC patch handled automatically. The pre-build script scripts/patch_lmic.py configures MCCI LMIC for the SX1262 radio and resolves a symbol conflict with libpp.a before every compile. No manual library edits required.

First boot — provisioning

On first boot the device derives its identity from the chip eFuse MAC, displays a QR code, and waits up to 5 minutes for the mobile app.

Device OLED during provisioning
1

Power on

The device derives a DevEUI from the chip's eFuse MAC using the IEEE EUI-64 rule, generates a deterministic default AppKey, and renders a QR code on the OLED.

2

Scan or connect via BLE

Open the Glustick Family app → Settings → Glustick Link → Add device. Scan the QR to pre-fill credentials, or tap "Set up via Bluetooth" and connect to GsfLink-XXXX.

3

App writes credentials via GATT

Eight characteristics are written in sequence: DevEUI, AppEUI, AppKey, server URL, PASETO token, WiFi SSID, WiFi password, kid's name. Values are staged in RAM until the commit write — an interrupted flow leaves NVS untouched.

4

Device reboots into normal operation

BLE advertising stops. The device joins LoRaWAN (up to 2 minutes) and connects to WiFi if credentials were provided.

QR code format

GSF:devEUI:appEUI:appKey
Example GSF:A8610A34567BFFFE:0000000000000000:A8610A34567BFFFE5A5A5A5A5A5A5A5A

Version-3 alphanumeric QR, ECC_LOW. Rendered at 2×2 px per module into the left 64×64 panel with a 3 px margin. Case-insensitive — the app accepts both GSF: and gsf:.

How it works

A simple state machine drives both transports. When WiFi and LoRa are both available, outbound messages go over WiFi. Inbound messages arrive via either path independently.

JOINING
OTAA join · up to 2 min
→
LORA_CONNECTED
LoRa only · 5 min ping
↕
WIFI_CONNECTED
HTTPS sync every 30 s
↔
IDLE
Display refreshes every 30 s
StateDescription
PROVISIONING BLE advertising active. OLED shows QR code and BLE name suffix.
JOINING LMIC OTAA join in progress. Can take up to 2 minutes on first attempt.
LORA_CONNECTED LoRaWAN joined, no WiFi. Outbound messages sent over LoRa. 5-minute keepalive ping.
WIFI_CONNECTED WiFi available. Messages synced over HTTPS every 30 s. LoRaWAN stays active as fallback.
IDLE Quiet. OLED refreshes every 30 s: kid name, RSSI (dBm), battery %, queued message count.
ERROR Unrecoverable failure. OLED shows error message. Power cycle required.

TLS is used for all WiFi sync. Self-signed certificates are accepted (setInsecure()), which is appropriate for a family-owned server on a home network.

Part of the Glustick ecosystem

Glustick Link firmware is one component of a self-hosted family communications stack.

Glustick Family

The Go backend these devices talk to. Handles routing, content filtering, and delivery through a unified pipeline.

Meshtastic

The recommended no-firmware-needed alternative transport. Flash and go — no gateway or infrastructure required.

meshtastic.org →

ChirpStack

Self-hosted LoRaWAN network server for the infrastructure path. Included in the Glustick Docker Compose lora profile.

chirpstack.io →

MCCI LMIC

LoRaWAN stack for Arduino. Handles OTAA join, Class A uplink/downlink, and the SX1262 radio HAL.
